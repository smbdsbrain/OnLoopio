# Reliability work (M00–M10)

This development branch retains Android 4.2.2/API 17, Java 8 bytecode, ARMv7 and the verified Type A firmware target. Release signing, TLS/hostname verification, the token-protected localhost proxy and public firmware ADB defaults are unchanged. The application version remains 0.10.1/code 17.

## Durable playback and queue

A queue occurrence has its own UUID, even when a song appears more than once. The saved session contains immutable display metadata, its account, source order, visited/forward history, pending permutation, repeat/shuffle, position and a separate listen attempt UUID. Queue rows are rewritten on edits; ordinary progress checkpoints update one small session row every ten seconds of advancing playback. A background writer serializes checkpoint, qualification and termination operations. Restore resets monotonic clocks and remains paused. A decoder seek has its own format-dependent error; process restart evidence does not prove physical power-loss durability.

Repeat Off stops at the end, including manual Next. Repeat One applies to natural completion; manual navigation exits it. Shuffle preserves the current entry and visited history. Play next has priority over the remaining shuffle order. Recovery visits a failed occurrence at most once until actual playback progresses. Pause, seek, focus, storage and queue changes invalidate prepared audio through operation epochs.

## Offline versions and publication

The main database upgrades additively from version 9 to 19: session/attempts (10), immutable generations (11), history/retry (12), partial transfers (13), gain (14), artifact variants (15), materialized readiness summaries (16), stamped gain provenance (17), indexed readiness lookup (18), and clock confidence/retry anchors (19). Existing aggregate play counts are retained without inventing historical events. The separate audio ownership index upgrades from 1 to 2 for its durable publication journal. Downgrading to an older APK after upgrading these schemas is unsupported.

A subscription has one active and one staging generation. A complete metadata update can stage independently of the full catalog. The active pointer switches only after every required token matches a completed registered file; overlapping files are shared and repeated occurrences count separately. Cancel/release and detached playlist handling preserve the active snapshot unless the user explicitly releases it. Reconciliation runs in the background after downloads and storage scans. Rendering uses materialized summaries rather than scanning SD.

Publication uses a durable partial, a private journal, registration and a same-volume rename. Recovery can finish an interrupted publication before or after rename and is idempotent. File completion checks include transport length, supported container headers and registered size/mtime. They do not detect every same-size corruption or a server replacing content under an unchanged ID without a validator. VFAT mtime comparisons use its two-second resolution. Physical SD failure is outside the SQL/filesystem recovery guarantee.

GC deletes only managed files for the selected account. Active/staging snapshots, the durable paused queue, current/prepared audio, download jobs and pins protect them. Protection currently retains all variants of a referenced song; this is deliberately conservative and can retain more bytes than necessary. Partials count against quota and free-space reserve. User-imported Music files are never automatic GC candidates. Explicit removal reconciles readiness immediately.

## Feedback, scheduling and audio variants

New listen attempts qualify after min(duration/2, 240 seconds) when duration exceeds 30 seconds; unknown duration needs 240 seconds. Short tracks remain in history. Advancing playback is measured monotonically; pause, stall and seek are excluded. Legacy pending events keep their original policy. The attempt ledger survives ACK and protects local counters from replay. History is separate from outbox and is pruned to 90 days/10,000 entries while protecting pending/current attempts.

Feedback can run with playlist refresh disabled and downloads paused. Each event/revision is acknowledged separately; bad individual records are held without blocking healthy records. Auth/TLS errors hold the account pipeline. Transient retries use 1/5/15/60 minutes, bounded jitter and persisted account-scoped state. Delivery is at-least-once: losing an HTTP response after the server committed a scrobble can produce a server duplicate, because the standard endpoint has no established client idempotency contract. Clock corrections cannot reconstruct an exact original wall timestamp. The original timestamp remains unchanged; implausible clocks, elapsed-time rollback or a wall/elapsed discrepancy over two minutes latch a durable uncertainty marker shown in history. Older records without anchors migrate as uncertain. Retry timestamps beyond the bounded horizon or newer than the current clock permit one attempt; account/quarantine holds remain in force.

Feedback, playlists, catalog and downloads share force-offline, home-network, USB and critical-battery guards. Automatic large work pauses at 20% and resumes at 25%; the charging profile defers large automatic work on battery. Workers own bounded wake/Wi-Fi locks; one-shot alarms do not accumulate missed jobs. No worker turns off a radio it did not own. Idle shutdown is opt-in, defaults to 30 minutes, and checkpoints/quiesces before using the existing privileged shutdown mechanism. Comparative battery measurements and real shutdown/USB tests require a signed system candidate.

Compatible retains legacy behavior, Original requests original bytes, and Compact requests MP3 192 kb/s. Variant tokens preserve older usable audio during a profile change. Original transfers resume only with a strong ETag and consistent 206/Content-Range/total; 200 restarts, 416 or a changed representation resets safely. Transcoding restarts from zero. Actual container/byte count is stored; requested bitrate is not a proven actual bitrate and is not presented as one.

ReplayGain is opt-in and attenuation-only. JSON getSong is bounded to 64 KiB/32 nesting levels, with an absent-data fallback for older servers. Optional signed finite gain/peaks are stored per source/variant with provenance and file stamps. Local ID3 TXXX/FLAC Vorbis tags are read with bounded scanning. Unknown transcoder normalization and Ogg decoder gain suppress additional normalization while retaining EQ headroom. Positive gain clamps to unity; EQ uses conservative positive-band headroom, without claiming a limiter. A synthetic wired -6 dB test produced reference-projection estimates of -6.44 to -5.11 dB with a WASAPI RAW request. WinMM estimates were -13.73 to -10.36 dB. RAW acceptance does not establish that hardware microphone processing is absent, and these estimates do not qualify musical fixtures or Bluetooth. The feature remains off by default.

Prepared-next playback is experimental, off by default, and restricted to local/completed WAV or FLAC, Repeat Off and EQ off. It checks completed file headers as well as source metadata, so Compact MP3 artifacts cannot inherit a FLAC/WAV eligibility label. It owns at most two MediaPlayers and retains the sequential fallback. Wired native tests measured 50 WAV and 50 FLAC boundaries within ±1 capture sample at 48 kHz after subtracting adjacent whole-file clock drift. Integrated service WAV and FLAC tests each passed 50 paired boundaries and recorded 150 distinct history attempts without scrobbles for short local fixtures. FLAC's final WinMM capture had 100 expected events, no clipping, and FD counts 48→52. A preceding long RAW capture timed out and is rejected as evidence. Native MP3 (LAME 320 kb/s with Xing, 1,105 samples of encoder delay and 431 samples of padding) passed 50 boundaries within the same precision, but integrated/multiple-encoder MP3 is not qualified. These are scoped measurements; Bluetooth, streaming and the full lifecycle/focus/edit matrix remain release gates.

## Reproducing development checks

Use JDK 17 and SDK 35. Run `gradlew.bat :app:assembleDebug :app:test :app:assembleDebugAndroidTest -PvalidationOnly --console=plain --no-daemon`. The property creates disposable `io.onloopio.validation` / `.validation.tests` packages and disables normal startup imports; never distribute this build. Production builds omit the property. An ordinary debug clone has no system USB mount permission and cannot qualify actual USB sharing. A release-signed system candidate is required for that gate.

The isolated device suite includes RuntimeStoreTest, PublicationTest, MetadataTest, PlaylistSyncTest, FeedbackStoreTest, CachePolicyTest, MusicStorageTest and PlaybackReliabilityTest. RuntimeStoreTest exercises fresh/baseline/sequential migrations, ACK deduplication, generation replacement and 10,000-entry checkpoints. PlaybackLifecycleProbe supports prepare, restore, pause-race, usb-denied and cleanup; the host force-stops the clone between prepare and restore. Full `usb` requires system privileges.

PipelineDeviceProbe uses disposable loopback TLS material from `tools/generate-network-fixture.py`, supplied at `/data/local/tmp/onloopio-crash-fixture.json`. It verifies genuine API17 TLS rejection/acceptance, JSON gain, independent catalog failure, poison isolation, interrupted original Range transfer and native decoding. Its service portion requires connected Wi-Fi and a clone without a real account, restores preferences and never contacts a real server. Remove generated keys after testing.

For wired measurement, generate continuous deterministic band-limited noise with `tools/generate-gapless-fixture.py`. Push reference/first/second files under `/data/local/tmp/onloopio-audio-fixture`. AudioOutputProbe explicitly supports WAV/FLAC/MP3 native pairs, gain, and integrated service-pair. Run a concurrent `tools/windows-audio-capture.py` recording on the explicitly selected input, then analyze using `tools/analyze-audio-capture.py`. The JSON records the correlation threshold, capture path and limitations. `tools/test-audio-analysis.py` verifies known sample insertions and attenuation with synthetic noise. Captures, device logs, certificates, private IDs and APKs belong outside Git.

`tools/windows-raw-audio-capture.cpp` is an optional Windows host helper. Build it from a Visual Studio developer shell with MSVC and the Windows 10 SDK (the Android build needs neither):

```powershell
cl /nologo /EHsc /std:c++17 /O2 /DNTDDI_VERSION=0x0A000000 /D_WIN32_WINNT=0x0A00 /Fo:local/raw-capture.obj /Fe:local/raw-capture.exe tools/windows-raw-audio-capture.cpp ole32.lib
local/raw-capture.exe Realtek 65 local/raw-gain.wav
python tools/analyze-audio-capture.py local/reference.wav local/raw-gain.wav --mode gain --capture-path wasapi-raw-requested --output local/raw-gain.json
```

It selects a unique active input by name substring, requests WASAPI RAW and fails if the request is refused. It writes channel zero as 48 kHz mono PCM16, limits duration to ten minutes, times out if capture stalls, and reports discontinuities. It never changes microphone levels/effects. Zero exit status and an accepted RAW request are prerequisites for using a capture, not proof of an unprocessed ADC path or a qualification verdict.
